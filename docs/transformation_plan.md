## 2. Design decisions

1. New backend code lives in a package `triage/`. Existing root modules (`predict.py`, `db.py`, `api.py`, `app.py`) are extended, not rewritten, and keep their public function names.
2. `predict_call()` keeps every existing return key and adds `assessment_state`, `reason_code`, `correlation_id`, `model_status`, and audit fields. Failure now returns `risk_flag="Assessment unavailable"` with the message `Assessment unavailable — follow standard procedure.` and `is_estimate=True`, which the existing UI already renders as UNSCORED.
3. `degraded` means a valid, integrity-verified score exists but a supporting component failed (calibration, explanation), or the v1 five-feature fallback model is used. The v1 fallback is OFF by default (`TRIAGE_ALLOW_V1_FALLBACK=false`) because a different model silently producing "Low risk" after a v2 failure violates rule 3. When enabled it is labelled `degraded` with reason `V2_UNAVAILABLE_V1_USED`.
4. Audit trail = two append-only SQLite tables (`assessment_audit`, `audit_events`) with SHA-256 hash chains and triggers that block UPDATE/DELETE. The only permitted deletion path is the retention purge, which writes an anchor to `audit_purge_log`.
5. Recording analysis uses a database-backed job table polled by a worker (in-process thread or CLI). No broker, no new service.
6. Default speech-to-text is a local provider that wraps `faster-whisper` if installed. It is not added to `requirements.txt`. When no engine is installed the job ends in `failed` with `TRANSCRIPTION_ENGINE_UNAVAILABLE`. Tests use a synthetic fixture provider that is refused outside local/test environments.
7. No microservices, queue brokers, or Kubernetes. Justification for each new dependency: `python-multipart` (FastAPI file upload, required), `hypothesis` (already imported by existing tests), `ruff` and `pip-audit` (dev/CI only).
